# ⚡ 私有协议智能逆向解析

中小企业进行老旧设备接入时，最痛苦的莫过于面对非标协议。手动编写 Netty 编解码器不仅耗时长，而且 CRC 校验算法稍有差错便会导致整帧解析失败。

---

## 智能逆向工作流

```text
 ┌────────────────────────────────────────────────────────┐
 │ 1. 输入阶段                                            │
 │    工程师粘贴抓包报文 (十六进制) 或上传 PDF/MD 通信协议手册 │
 └───────────────────────────┬────────────────────────────┘
                             │
                             ▼
 ┌────────────────────────────────────────────────────────┐
 │ 2. AI 推理阶段                                         │
 │    · 识别帧头 (Header) 与帧尾 (Tail)                    │
 │    · 识别从站地址域、功能码、长度域                     │
 │    · 逆向推导校验和算法 (CRC16-Modbus, LRC, CheckSum8)  │
 │    · 映射物理属性点位 (温度、电压、开关状态)            │
 └───────────────────────────┬────────────────────────────┘
                             │
                             ▼
 ┌────────────────────────────────────────────────────────┐
 │ 3. 代码生成阶段                                        │
 │    · 生成符合 yudao-module-iot-gateway 标准的 Java 类   │
 │    · 继承自 AbstractProtocolDecoder / AbstractEncoder   │
 │    · 自动生成完整的 JUnit 5 单元测试用例                │
 └────────────────────────────────────────────────────────┘
```

---

## 样例：从原始报文到生产代码

**输入原始抓包**：
```text
AA 55 01 03 04 01 2C 00 FA D2 4B
```

**AI 逆向分析结果**：
- `AA 55`：双字节定长帧头；
- `01`：设备站号 (Device ID = 1)；
- `03`：查询保持寄存器命令；
- `04`：后续数据载荷长度为 4 字节；
- `01 2C`：寄存器 1 数值（十进制 300，对应温度 30.0℃，缩放系数 0.1）；
- `00 FA`：寄存器 2 数值（十进制 250，对应压力 2.50 MPa，缩放系数 0.01）；
- `D2 4B`：CRC16/MODBUS 循环冗余校验码。

系统直接输出可直接编译执行的 Netty Decoder Java 代码，并附带通过断言验证的单元测试，将设备调试接入周期从两周压缩至半小时以内。
